# Sprint 1, Part 3 — Environment Standard

**Status:** final. **Source of truth:** `server/app/config.py`'s `Settings` class — every variable that exists in this application is declared there; this document does not add any variable the code doesn't already read. **Method:** each variable checked directly against its usage (`grep`), not assumed from its name.

## Complete reference

| Variable | Classification | Default | Used by | Notes |
|---|---|---|---|---|
| `ENVIRONMENT` | **Required** | `development` | `main.py::_validate_production_config`, HSTS header logic | Must be exactly `production` in every real deployment for the boot-time secret validation and HSTS header to activate. Any other value is treated as non-production. |
| `DATABASE_URL` | **Required, Secret** | `postgresql+psycopg://payreality@localhost:5432/payreality_dev` | `db/session.py` | Contains embedded credentials; never has a safe non-secret default. Render's `sync: false` marker in `render.yaml` already treats it correctly. |
| `OPA_URL` | Optional | `http://localhost:8181` | `intent_service.py`, `runtime_policy_service.py`, `/health/ready` | Correct default for the embedded-OPA topology; only needs overriding if OPA ever moves to a separate service. |
| `OPA_BINARY_PATH` | **Unused** | `opa` | *(none found)* | Declared in `Settings` but zero references anywhere else in `server/app` — confirmed by direct search. Not a secret, not required, not actually read by any code path today. Recorded here as a finding, not a variable to configure. |
| `EVIDENCE_SIGNING_KEY_B64` | **Required in production, Secret, Generated** | `""` | `intent_service.py` (signing), `evidence_service.py` (verification), `signing_key_service.py` (rotation registry) | Boot-time validation refuses to start in production without this. A base64-encoded ED25519 seed — generate per environment, never share between staging and production. |
| `EVIDENCE_SIGNING_KEY_ID` | Optional, should be set per environment | `signing_key_dev` | same as above | Not enforced by boot-time validation today (a gap — see [04_SECRETS_MANAGEMENT_GUIDE.md](04_SECRETS_MANAGEMENT_GUIDE.md)), but must be distinct per environment/key generation in practice, since it's the label the signing-key registry keys on. |
| `ADMIN_API_KEY` | **Required in production, Secret, Generated** | `""` | `security.py::verify_operator_key` | Boot-time validation refuses to start in production without this. Full-bypass credential — see [04](04_SECRETS_MANAGEMENT_GUIDE.md) for its rotation gap. |
| `ANTHROPIC_API_KEY` | Optional, Secret | `""` | AI Policy Builder, AI Authority Builder (`claude_provider.py`, three call sites) | Genuinely optional: every AI-feature endpoint checks for its presence and degrades to a `configuration_required` state rather than erroring when absent. Not needed for the platform's core Runtime Authority path at all. |
| `INTENT_SIGNATURE_WINDOW_SECONDS` | Optional | `300` | `routers/intents.py` (replay-window check) | A security-relevant tuning parameter, not a secret. |
| `CORS_ORIGIN` | **Required in production** | `http://localhost:5173` | `main.py` (`CORSMiddleware`) | Boot-time validation refuses to start in production if this is missing *or* still at its dev default — the one variable validated for content, not just presence. |
| `ORGANIZATION_NAME` | Optional | `PayReality` | `main.py::_bootstrap_organisation_owner` | Only consulted once, during the one-time Owner-bootstrap on first boot; a no-op on every later boot once that row exists. |
| `OWNER_EMAIL` | Optional | `owner@payreality.local` | same as above | Same one-time-bootstrap scope as above. Should be set to a real address before first production boot — the default is a placeholder, not a functioning owner account. |
| `RENDER_GIT_COMMIT` | **Generated by the platform** | *(none — absent outside Render)* | `main.py`'s `/version` endpoint | Never set by a human or a `.env` file; Render injects this automatically on every deploy. Falls back to `"unknown"` outside Render (e.g. under `docker-compose`), which is correct, not a bug. |

## Per-environment expectations

| Variable | Local/Development | Staging | Production |
|---|---|---|---|
| `ENVIRONMENT` | `development` | `production` | `production` |
| `DATABASE_URL` | local/docker-compose Postgres | staging Render Postgres | production Render Postgres (paid tier, per [02](02_INFRASTRUCTURE_BLUEPRINT.md)) |
| `EVIDENCE_SIGNING_KEY_B64` / `_ID` | a locally-generated dev key, never reused elsewhere | its own, distinct key | its own, distinct key — **never** the same key material as staging or local |
| `ADMIN_API_KEY` | a local dev value | its own, distinct value | its own, distinct value |
| `CORS_ORIGIN` | `http://localhost:5173` | the staging frontend's URL | the production frontend's URL |
| `ANTHROPIC_API_KEY` | optional, can be left empty | optional | set, if AI features are enabled for real customers |

**Setting `ENVIRONMENT=production` on staging is deliberate**, not a naming mismatch: staging exists specifically to rehearse production's exact boot-time validation and header behavior. If staging ran with `ENVIRONMENT=development`, a missing-secret bug that would crash production on boot could sit undetected in staging indefinitely.

## Findings from this inventory

- `OPA_BINARY_PATH` is dead configuration — declared, documented in `.env.example`, never read. Not urgent to remove (it's harmless), but worth a one-line cleanup so a future reader doesn't assume it does something.
- `EVIDENCE_SIGNING_KEY_ID` and `ANTHROPIC_API_KEY` are not covered by `_validate_production_config`'s boot-time check, unlike the other three secrets. `ANTHROPIC_API_KEY`'s omission is correct (it's genuinely optional). `EVIDENCE_SIGNING_KEY_ID`'s omission is a smaller, real gap — production could theoretically boot with the dev-default key *id* label while using a real key *value*, which would work but mislabel the signing-key registry. Flagged for [08_ENGINEERING_IMPLEMENTATION_PLAN.md](08_ENGINEERING_IMPLEMENTATION_PLAN.md).
