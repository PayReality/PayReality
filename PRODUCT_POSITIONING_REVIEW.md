# Product Positioning Review

A direct audit of every public-facing claim against the platform actually shipped across Milestones 1-7, not against what the website says about itself. The website audit covered every page under `src/app/pages/` in the `Payreality-website` repo (this session's own working directory), the nav/footer source of truth, and the root README. Findings are grouped Correct / Outdated / Incorrect / Missing, per Phase 1's own required structure. VERIFIED means checked directly against shipped code or a live system; INFERRED means a reasonable conclusion; PROPOSED means a recommendation.

## Headline finding, read this first

**The website's technical pages, and its own structured data fed to search engines, claim the core runtime is built in Rust with gRPC.** VERIFIED, directly, against seven milestones of hands-on engineering on this exact codebase: `server/app/` is a Python FastAPI application (confirmed again just now via `server/pyproject.toml`: `fastapi>=0.115`, `uvicorn`), communicating over plain HTTP/JSON, not gRPC. There is no Rust code anywhere in this repository at any point across this engagement. This claim appears repeatedly and prominently: `products/RuntimeAuthority.tsx` (marketing), `founders/NathanObiekwe.tsx` and `founders/SeanChihwendu.tsx` (founder bios), `Leadership.tsx`, and `index.html`'s own JSON-LD structured data, meaning it is not a single stray sentence but a claim search engines and any technical due-diligence reader will find consistently repeated. This is the single highest-priority correction in this entire review; everything else here is secondary to it. See the Incorrect table below for the specific fix, and this document does not apply it unilaterally, since it touches founder-voice copy and structured data across many files, without first confirming with the user whether "Rust/gRPC" describes a real, separate component this engagement never touched, or whether it is simply wrong and should become "Python (FastAPI), OPA and Rego for policy evaluation, HTTP/JSON."

## Correct (verified, keep as-is)

- **The site already avoids exactly the buzzwords Phase 3 asks to remove**, and does so more thoroughly than this milestone's own brief assumed. `resources/Faq.tsx` explicitly states *"it's not an AI governance platform"*; `WhyWeExist.tsx` explicitly rejects the word "governance" as the category name; `Manifesto.tsx` explicitly buckets "governance, compliance, monitoring, audit, and observability" as "detective controls" and positions Runtime Authority as a "preventive control" instead. No page uses "AI observability" or "agent monitoring" as self-description. This is a real, already-shipped positioning discipline; Phase 3 of this milestone should preserve and reinforce it, not treat buzzword removal as unstarted work.
- **ED25519 signing, OPA/Rego policy evaluation, fail-closed behavior, and the three-outcome (ALLOW/DENY/HUMAN_REVIEW) model**: every one of these claims matches the shipped platform exactly, VERIFIED across this entire engagement, including live production validation as recently as Milestone 7.
- **Six fixed platform roles** (Owner, Governance Administrator, Agent Administrator, Reviewer, Auditor, Executive): matches the real, shipped RBAC model exactly (Milestone 3).
- **"Python SDK only, other languages planned, not started"**: matches reality exactly; no partial Node/Go/Java/.NET/Rust SDK exists.
- **No SOC 2/ISO 27001 certification, stated plainly on the Security page**: still accurate, matches this milestone's own Launch Readiness finding.
- **No customer names, logos, or case studies anywhere on the site**: consistent with reality (no completed pilot, no reference customer, per the Pilot Program Guide).
- **The `demo.aisecurewatch.com` "View Platform" link is explicitly commented in code as the public, credential-free demo, not the real product**: consistent with this engagement's own prior work building that demo environment.

## Outdated (was true, no longer is)

- **Security page's disclosed limitation, "a single shared operator credential can act with full admin authority org-wide, not yet scoped per-user."** This was true before Milestone 2 and is no longer the whole story: the Operator Key was made platform-admin-only (Milestone 2), and a real, six-role, permission-based RBAC system now governs ordinary organization access (Milestone 3), live and tested. The site is **underselling** its own security posture here, not overselling it, an unusual direction for a marketing gap but still a real inconsistency between the site and the product. **PROPOSED fix**: update this section to describe the current model (RBAC with six fixed roles for ordinary access; the operator credential now reserved for genuine platform-admin, cross-organization actions only) rather than the pre-Milestone-2 state.
- **The dashboard's own `OrganizationSettingsPage.tsx` states "Azure OpenAI and AWS Bedrock have no integration built yet, shown honestly."** VERIFIED this is now stale: Azure AI Foundry integration for both Authority Builder and (as of Milestone 6) AI Policy Builder is real, live, and was proven via a genuine extraction with non-templated model output in Milestone 6, then re-verified through production in Milestone 7. The banner logic itself (`AiComingSoonBanner`, gated on a live `ai_enabled` flag from the backend) is architecturally sound and should already reflect this correctly at runtime; the specific static sentence on the Organization Settings page was not updated when Foundry integration shipped and should be.
- **`README.md`'s file/path references**: describes pages as `PolicyEngine.tsx`, `Sdk.tsx`, and content under `/docs/*`; the actual current files are `RuntimePolicies.tsx`, `Sdks.tsx`, under `/developers/*` (`/docs/*` is now redirect-only). **This document corrects this directly, see below.**
- **`README.md`'s stated "Launch Platform" demo URL, `payreality.aisecurewatch.com`, does not match the actual `PLATFORM` constant in code, `demo.aisecurewatch.com`.** A real, checkable drift between documentation and code. **This document corrects this directly, see below.**

No other claim surfaced in the website audit contradicts verified platform behavior. This is a genuinely narrow, single-item Incorrect list, which is itself informative: the site's factual claims are, with this one significant exception, accurate.

## Missing (capabilities that exist but aren't described)

- **Multi-tenancy and Enterprise Surface Isolation** (Milestones 2-3): the site never mentions that the platform is multi-tenant at all, let alone that isolation was tested with a real second organization. For an enterprise buyer, "your data is isolated from every other customer, and here is how we proved it" is a stronger, more specific claim than anything currently on the Security page, and it is fully earned.
- **The real Azure production architecture** (Milestones 4-7): no page names Azure, Container Apps, Key Vault, Managed Identity, AI Foundry, or AI Search as PayReality's own live infrastructure. The Security page deliberately keeps hosting generic ("our hosting providers"); given the infrastructure is real, live, identity-first, and genuinely differentiated (no shared static credentials where Managed Identity suffices), naming it specifically is a missed opportunity, not a prudent generalization. Azure AI Foundry is currently listed only as a "Coming Soon" *customer-facing* integration, which is a different, valid claim from "PayReality's own Authority Intelligence pipeline already runs on Azure AI Foundry today," a stronger, verified statement the site does not make anywhere.
- **The Runtime Policy Simulator** (Authority Intelligence Program Phase 4, fixed and live-verified in Milestone 6): a real, working, saved-scenario-and-batch-CSV capability that lets a reviewer test a policy change before it goes live. Not mentioned anywhere on the current site; it's a concrete, demoable, differentiated feature.
- **Evidence chain verification and signing-key rotation**: the site describes per-decision signing but not the hash-chain-across-decisions property or the signing-key registry that keeps historical Evidence verifiable after a rotation, both real, both differentiated.
- **A live, real conference/investor demo path**: nothing on the site currently states, as this milestone's own Launch Readiness assessment can now state truthfully, that a visitor can watch a real document produce a real extraction produce a real policy produce a real signed decision, live, not a recording.

## Consistency across artifacts

The audit found the website internally consistent with itself (its own product pages, developer pages, and founder bios agree with each other almost everywhere, the Rust/gRPC claim included, which is precisely why that claim is a real risk rather than a typo: it's been repeated consistently, not stated once and forgotten). The one real internal drift found was `README.md` against the live `site.ts` code, corrected below. This review did not find a separate LinkedIn, pitch deck, or sales-doc corpus to check consistency against; those did not exist as artifacts prior to this milestone, since `SALES_ENABLEMENT_PACK.md` (this milestone's own deliverable) is the first sales material this engagement has produced. Going forward, that document, not this website, should be treated as downstream of `ENTERPRISE_MESSAGING_GUIDE.md`; this review exists to catch the website up to the same standard, not to duplicate it.
